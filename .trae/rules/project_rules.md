# Shell脚本项目规则配置引导

## 1. 项目概述

本项目是一个Linux系统初始化脚本集合，主要用于自动化配置和优化Linux 镜像的自动配置的开发环境。通过运行脚本，可以快速设置系统参数、安装必要软件、配置网络代理等，提升开发效率。
主要目的在于方便用户在下载OSbox vmimage 等镜像的时候，快速完成配置工作。

## 2. 编码规范

### 2.1 基本语法规范

1. **Shebang声明**：所有Shell脚本文件必须以`#!/bin/bash`开头
2. **编码格式**：使用UTF-8编码
3. **行结束符**：使用Unix风格的LF(\n)而不是Windows的CRLF(\r\n)
4. **缩进规范**：使用制表符(tab)进行代码缩进，保持代码层次清晰

### 2.2 变量命名规范

1. **命名风格**：采用小写字母加下划线的命名方式，如`os_version`
2. **常量命名**：全部大写，如`MAX_RETRY_COUNT`
3. **全局变量**：应尽量避免使用全局变量，如需使用应添加注释说明
4. **变量作用域**：函数内部变量使用`local`关键字声明

### 2.3 函数规范

1. **函数命名**：采用小写字母加下划线的命名方式，如`install_deps`
2. **函数注释**：每个函数都应有注释说明功能、参数和返回值
3. **参数处理**：使用`$1, $2, ...`或`shift`处理参数
4. **返回值**：正确使用return语句返回状态码

### 2.4 注释规范

1. **文件头注释**：每个脚本文件开头应包含功能说明、作者、创建时间等信息
2. **函数注释**：说明函数功能、参数、返回值
3. **关键代码注释**：对复杂逻辑或关键步骤添加注释
4. **中文注释**：项目中可以使用中文注释，但要保持一致性

## 3. 安全规范

### 3.1 权限检查

1. **root权限检查**：涉及系统配置的脚本必须检查是否具有root权限
2. **sudo权限检查**：对于需要sudo权限的操作，应先检查用户是否具有sudo权限
3. **权限最小化**：只请求必要的权限，避免过度授权

### 3.2 输入验证

1. **参数验证**：对所有输入参数进行有效性检查
2. **路径验证**：对文件路径进行验证，防止路径遍历攻击
3. **命令注入防护**：避免直接执行用户输入的内容

### 3.3 错误处理

1. **set -e**：在脚本开头使用`set -e`确保遇到错误时立即退出
2. **错误捕获**：使用`trap`捕获信号和错误
3. **日志记录**：记录关键操作和错误信息
4. **优雅退出**：提供清理函数确保脚本异常退出时能清理资源

## 4. 项目结构规范

### 4.1 目录结构

```
project/
├── .trae/
│   └── rules/
│       └── project_rules.md  # 项目规则配置文件
├── OSinit.sh                 # 系统初始化主脚本
├── OSuninit.sh               # 系统还原脚本
├── testinit.sh               # 测试脚本
└── README.md                 # 项目说明文档
```

### 4.2 文件命名规范

1. **脚本文件**：使用小写字母，单词间用下划线分隔，如`install_deps.sh`
2. **配置文件**：使用小写字母，以`.conf`或`.cfg`结尾
3. **临时文件**：统一放在`/tmp`目录下，使用随机名称
4. **日志文件**：统一放在`/var/log`目录下或项目内的`logs`目录

## 8. 版本控制规范

### 8.1 分支管理

1. **主分支**：`main`分支用于发布稳定版本
2. **开发分支**：`dev`分支用于日常开发
3. **功能分支**：新功能开发应在独立分支进行

### 8.2 提交规范

1. **提交信息**：提交信息应清晰描述变更内容
2. **原子提交**：每次提交应只包含一个逻辑变更
3. **代码审查**：重要变更应经过代码审查

## 9. 性能优化建议

1. **避免重复计算**：缓存计算结果避免重复执行
2. **减少外部命令调用**：合并多个命令减少系统调用次数
3. **合理使用管道**：避免不必要的管道操作
4. **内存管理**：及时清理不需要的变量和临时文件

## 10. 最佳实践

1. **使用绝对路径**：在脚本中尽量使用绝对路径
2. **环境变量检查**：使用前检查环境变量是否存在
3. **日志输出**：提供详细的操作日志输出
4. **用户交互**：必要的用户交互应提供清晰的提示信息
5. **备份机制**：修改重要配置前应进行备份
6. **回滚机制**：提供配置回滚功能
